## Status at v1.0.2 ship (2026-05-19)

Refactor-only release on top of v1.0.1. No consumer-visible behavior
change — byte-diff golden BBCode regression unchanged pre/post. What
changed is the dbt DAG itself: new contract layer between seeds/int
and consumers, a promotion from intermediate to mart, and a bunch of
denormalization that simplifies downstream filtering.

What shipped:

- **New mart-layer contracts.** `dim_stat` (over `stat_classification`),
  `dim_matchup_period` (over `matchup_schedule`), and
  `fct_player_daily_performance` (over `int_player_daily`). Output
  scripts and dbt models now route through these instead of reaching
  past the marts layer.
- **`int_player_weekly_performance` promoted** to
  `fct_weekly_player_performance` — renamed, moved from
  `intermediate/` to `marts/`, re-sourced from
  `fct_player_daily_performance`. Materialized as a table (was a
  view). The daily-to-weekly DAG edge is now load-bearing.
- **Schedule columns denormalized onto the four weekly facts.**
  `is_abnormal` / `is_playoff` / `playoff_round` now live as columns
  on each weekly fact (sourced from `dim_matchup_period`). Consumers
  filter abnormal weeks and render week labels directly off rows;
  several historical-count SQL queries dropped their
  `matchup_schedule` JOINs as redundant.
- **Single source of truth for the seed → leaderboard name
  translation.** `dim_stat.leaderboard_name` is the only place the
  mapping lives now. `output/stat_catalog.py`'s `SEED_TO_LEADERBOARD`
  + `to_leaderboard_name` removed; the duplicate CASE block in
  `mart_stat_leaderboard.sql`'s compile-time loop removed (it now
  reads `leaderboard_name` from dim_stat via `run_query`).
- **DAG hygiene.** dbt exposures rewired through the new contract
  layer (no more direct edges from seeds/int to consumer outputs);
  `weekly_recap` gains `mart_league_weekly_benchmarks` (which was
  added at v1.0.1 but never declared on the exposure);
  `mart_stat_leaderboard.current_year` CTE moved from `raw.box_scores`
  to `fct_weekly_team_active_performance` (one less raw edge on the
  visible DAG).

## Status mid-v1.1.1 (2026-05-26) — optimal-team primitive shipped

Continuation of the in-flight v1.1.1 refactor. v1.1.1 is still not
tagged; this session's work is the get_optimal_team generalization
that was scoped at the previous session's close.

### What shipped this session

**New dbt model:**

- **`int_player_position_pts`** (view): per-position points
  accumulation at matchup grain, sourced from
  `fct_player_daily_performance` via `LATERAL FLATTEN` of
  `eligible_slots`. Approach 1 to the eligibility question per
  BRAINTHOUGHTS [ARCH] discussion: a player's points at position P
  on day D = their `platform_points` on days they were eligible at
  P, summed across the matchup. BE / IL filtered out (roster
  slots, not lineup positions). Combined ESPN codes (CI / MI / P /
  1B/3B / 2B/SS) kept as-is since they appear in the data even if
  this league's roster shape doesn't currently use them.

  Points are decomposed by stat category: pitching positions
  (SP / RP / P) get the player's `platform_pitching_pts`,
  everything else gets `platform_hitting_pts`. For ~99% of players
  (single-discipline) this equals raw `platform_points`; for
  two-way players (Shohei) it correctly attributes pitching
  production to pitching-position rows and hitting production to
  hitting-position rows so the disjoint-stat-categories selection
  rule can pick them at one of each without double-counting.

  Two stored point columns: `active_pts` (days slotted active) and
  `inactive_pts` (days slotted BE / IL / FA). An `all` lens is
  derived at consumer time as `active + inactive`; no separately
  rounded `all_pts` column to avoid a 0.1-scale rounding gap from
  independently rounding three SUMs.

**Three new Python primitives:**

- **`get_optimal_team_candidates(season_year, matchup_period,
  team_id, points_type)`** in `output/almanac_data.py`:
  parameterized dispatcher returning the candidate pool from
  `int_player_position_pts`. Every parameter is optional; `None`
  means "no filter on this dimension." Supports all 15 viable
  (timespan x scope x points_type) combinations. Pool ordered by
  `(position, position_pts DESC, player_id)` so downstream
  selection is deterministic.
- **`get_optimal_team_selections(candidates, slot_caps)`** in
  `output/almanac_logic.py`: gap-based selector. At each step
  fills the slot type where the gap between top and second-best
  eligible candidate is largest -- "fill the slot where picking
  2nd-best hurts most." Iterates `slot_caps` keys (not Python's
  set ordering) so tie-breaking is byte-deterministic. Disjoint-
  stat-categories rule: a player can fill at most TWO slots, and
  only if the two are in different categories (hitting vs
  pitching). This is the Shohei rule baked in.
- **`get_optimal_team(season_year, matchup_period, team_id,
  points_type)`** in `output/almanac_data.py`: convenience
  function chaining candidates + selection + stat-line enrichment.
  Returns rendered-ready rows for `format_all_league_team_row`
  including `platform_points`, `lineup_slot`, `slot_rank`,
  `slot_label`, the full set of TOP_SCORER stat columns, and
  `period_label='Season'` set for non-matchup-specific calls (so
  the renderer suppresses the per-row boxscore URL).

**Wrapper repoint:**

- `get_all_league_team(season_year, matchup_period=None)` is now
  a 5-line delegation to `get_optimal_team(... points_type=
  'active')`. The two private helpers
  (`_get_all_league_team_for_week`,
  `_get_all_league_team_season_to_date`) are deleted (228 lines).

**Stat-line enrichment:**

- `_enrich_optimal_team_with_stats(...)` in `almanac_data.py`
  runs a second SUM aggregation over
  `fct_weekly_player_performance` for the selected player IDs,
  scoped to the same filter window. Merges all 62 stat columns
  (31 counting + 31 `_pts`) into the selected rows in-place so
  the renderer's `format_top_scorer_stats_line` produces the
  player-stat-tail unchanged from the pre-v1.1.1 format. For
  week-specific queries the sum is a no-op (single source row);
  for broader windows the tail represents accumulated production
  across the filter window.

**Fix: missing imports in `almanac_write.py`.** Earlier today,
caught that the Tier 2c.4 split moved `write_almanac` into
`almanac_write.py` but didn't carry over `os`, `re`, and
`records` imports. The byte-diff test exercises the build side
via `--no-sheets`, which masked the gap; first live-write attempt
would have crashed at module load. 3-line import addition.

## v1.x priorities

Items pulled from `ROADMAP.md` Now bucket plus open product calls.
Each has a plain-English header for skim, then the technical detail
beneath.

### **Player Profiles** (v1.x flagship)
Build the player-as-entity layer the project has been missing.
`dim_player` is a slowly-changing dimension carrying current MLB team,
position, eligibility — absorbs the per-day display lookups that
consumer scripts currently reach into `int_player_daily` for.
`fct_player_career` is the career-aggregate fact (total fantasy teams
played for, career stats, transaction history derivable from box
scores). Most data is already in the pipeline; bio/draft additions are
a v2.x extract follow-on.

### **Stat Catalog Cleanup**
Three small changes to `stat_classification.csv` that have been
queued since Phase 7 surfaced them:
- Split `is_always_tracked` into `is_record_force_surface` +
  `is_tracked` (current column does double duty; the conflation
  surfaced during Phase 7 B1 review)
- Flag `NEGATIVE_POINTS` as a record candidate (column exists on all
  4 facts; just needs the seed flip to surface "Most Negative Points"
  callouts in the recap)
- Promote stat 30 (Hit for the Cycle) from `is_record_candidate=false`
  to true; pair with a `league_notes.py` "First cycle of the season!"
  callout. Discovered during Phase 7 F-prep (15-pt scoring weight,
  2 real candidates over 2 seasons)

### **Recap Polish**
Smallish output-rendering tweaks, no architectural risk:
- "No active no-hitters yet" rendering for stats where rank-1 = 0 with
  `is_always_tracked=false`. Currently the records section reads as if
  a record exists when none does
- Conditional 3rd "Top Scorer" line — drop it when the overall winner
  didn't have both non-zero hitting AND pitching contributions (it's
  often a duplicate of Top Hitter or Top Pitcher otherwise)
- Round one-decimal points at the fact layer to eliminate the cosmetic
  126.9 ↔ 127.0 ping-pong on summation-order changes

### **Sheets Sink Hardening**
The `_replace_tab` flow currently does `worksheet.clear()` + `update()`
which wipes user-applied formatting (colors, frozen rows, column
widths). Switch to in-place `update()` for the data range plus
targeted `batch_clear` for trailing rows when the new dataset is
smaller. Verify by hand-formatting a tab, running, and confirming
formatting survives.

### **Records Logic Cleanup**
Two code-organization tweaks:
- Dependency-inject `count_value_occurrences` into `collapse_ties`.
  Right now `records_logic.collapse_ties` has one explicit
  `from records_data import count_value_occurrences` for the
  saturated-tier backfill — the only logic→data import. Replacing it
  with a `count_fn` parameter keeps `records_logic` truly pure and
  enables unit-test coverage of the saturated-tier branch
- Factor shared boilerplate (`output/_setup.py`): UTF-8 stdout
  reconfig + dotenv + schedule lookup are duplicated across both
  consumer scripts

### **Owner Names in the Mart**
Wire `owner_nicknames.csv` into the dbt staging layer so owner display
names propagate through the mart. Today the seed exists but isn't
joined; output scripts read it ad-hoc (works, but the mart should
carry the canonical value).

### **Playoff Contention Identification**
During playoff weeks, all teams still play (consolation bracket); the
records output today can't distinguish a Finals MVP performance from
a 13th-place consolation week. Identifying which (team, season,
matchup_period) tuples represent actual playoff contention would let
records filter or annotate accordingly. Discovery TBD on what
playoff-bracket data ESPN's API exposes — may push to v2.0 if it
needs a new extract path.

### **Calendar Auto-Populate**
`matchup_schedule.csv` is currently a hand-maintained seed (~25 rows
per season). Most fields are derivable from
`espn-api`'s `league.settings`: `matchup_periods` dict, `regular_
season_count`, `playoff_team_count`. Only `is_abnormal` (All-Star
break, weather-shortened weeks) stays manual. Proposed shape:
extract → `raw.matchup_schedule` (append-only); new
`stg_matchup_schedule` joins to a tiny `matchup_schedule_overrides.csv`
seed for `is_abnormal` patches. Maintainer has additional automation
heuristics — confirm scope before writing code.

### **League-Wide Benchmarks**
Records today are per-team. Ungrouping for league-wide weekly
aggregates ("this week we averaged 250 points, 70th percentile in
league history") unlocks collective-mood callouts in the recap. Small
change — new view over existing facts.

### **Career Stats Per Team**
`fct_team_career_stats`: career-aggregate counterpart to
`fct_weekly_team_active_performance`. Powers "who has the most points
scored for their team in league history" callouts — fun for the
keeper-league framing. Data's already there; this is just an
aggregation layer. Companion to the `fct_player_career` flagship work.

## Conventions worth preserving

These worked in Phase 7. Keep them.

- **Commit messages: first-person, no AI attribution.** The pre-push
  sweep stripped Co-Authored-By trailers and reworded a few
  internal-y subject lines. New commits should match the style:
  technical, clear, no "the user" / "we" / Claude references.
- **Per-piece review cadence.** Big drafts (CHANGELOG, README, Phase
  retrospectives) get shown for review before commit. Small mechanical
  changes commit directly. Push to origin happens explicitly, not
  automatically.
- **dbt build + warehouse pytest before any model change ships.**
  Golden BBCode regression catches output drift; treat a red test as
  a stop-the-line.
- **Phase doc convention for major retrospectives.** Substantive
  rearchitects get a `Phase X.Y Documentation.md` entry. v1.x doesn't
  necessarily need this if the work is incremental polish — only if a
  v1.x release is genuinely Phase-shaped.
- **Current-state framing in `schema.yml` descriptions.** Don't re-add
  Phase X.Y prefix references; chronology lives in CHANGELOG and Phase
  docs. Same convention for `output/*.py` module docstrings.
- **"Decided Against" rather than "Won't Do"** in ROADMAP. The phrase
  signals "we considered this and the answer is no for these reasons,"
  which reads better than dismissive phrasing.

## Don't-touch list (operational)

weekly post or league members' expectations. Surface before merging
any change that touches them.

- Header conventions: `[u][b]Section[/b][/u]`, `[b]Label[/b]: value`

- "Matchup #N" → "Week N" everywhere
- Playoff weeks render as round names (`Round 1` / `Semi-Finals` /
  `Finals`), not as `Week 24-26`
- Legacy 17-column records Sheet schema across 3 tabs
- v1.1 almanac tab shapes unless intentionally changing product output
- `SHEETS_OUTPUT_ID` env-var opt-in for Sheets sinks (not opt-out)
- `output/LeagueNote.txt` appended verbatim under "Additional Notes"
- BBCode renderer constraint: ESPN supports only `[b]` `[u]` `[i]`;
  no hyperlinks, images, or other tags
